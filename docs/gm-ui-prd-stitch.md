# GM 工具前端重设计 PRD 与 Stitch 原型提示

## 1. 产品定位

GM 工具是内部游戏运维与测试控制台，核心用户是 GM、测试、研发和管理员。页面的主要任务不是展示数据，而是让用户快速确认环境、选择账号、执行命令或脚本，并在执行前后明确看到状态。

## 2. 设计参考

参考方向来自 Dribbble 的游戏后台、服务器控制台和深色侧边栏管理台：

- https://dribbble.com/search/game-control-panel
- https://dribbble.com/search/admin-console
- https://dribbble.com/search/dark-sidebar
- https://dribbble.com/shots/26695476-Game-Hub-Admin-Panel-Dashboard-UI-Design

设计应吸收它们的高完成度，而不是复制营销式视觉。GM 工具属于高频操作台，必须保留清晰、稳定、可扫描的工作流。

## 3. 用户目标

- 快速判断当前是否已连接客户端、KS 环境是否可用。
- 在分类、环境和账号之间快速筛选目标。
- 对需要额外参数的 GM 命令直接输入参数后执行。
- 管理脚本、命令、公式、Skill、Git 拉取和用户权限。
- 在桌面和窄屏窗口里都能完成核心操作。

## 4. 信息架构

一级导航保持现状：

- 命令管理
- 脚本管理
- 测试设计
- Skill 管理
- 计算公式
- 道具表
- Git 拉取
- KS 环境同步
- 用户管理

命令管理首屏顺序：

1. 页面标题和数量状态
2. 搜索、分类筛选、查询、清空、新增、分类管理
3. KS 游戏账号与环境选择
4. 命令分组列表
5. 命令详情弹窗

## 5. 视觉方向

名称：Game Ops Control Deck

页面采用深色侧栏和浅色任务区的组合。深色侧栏体现控制台属性，浅色任务区保障长时间阅读与批量操作。主色只使用蓝绿色，用于当前选择、主按钮、可执行状态和关键焦点。

颜色：

- Cockpit Ink: `#111b26`
- Rail Ink: `#182635`
- Work Surface: `#f3f7fa`
- Panel White: `#ffffff`
- Command Teal: `#08796f`
- Line: `#d7e1e8`
- Text: `#14202b`

字体：

- UI: Segoe UI Variable / Segoe UI / Microsoft YaHei UI
- Code: Cascadia Mono / Consolas

形状：

- 面板、按钮、输入框统一 8px 以下圆角。
- 只有小状态标签使用 pill。
- 不使用大面积渐变、发光阴影、装饰网格。

## 6. Stitch 生成提示词

请生成一个内部游戏 GM 运维控制台原型，名称为 GM Command Center。

页面是后台操作台，不是官网。使用深色左侧导航栏和浅色主工作区。视觉风格参考 Dribbble 上的 game admin dashboard、server control panel 和 dark sidebar admin console，但要保持企业级运维工具的清晰度。

首屏包含：

- 左侧导航栏，带 GM 标识、功能入口、管理员信息、修改密码、退出登录、缩放、主题切换。
- 主区域顶部标题为“命令管理”，右侧显示“共 128 条”状态。
- 紧凑工具栏：搜索框、分类下拉、查询、清空、新增命令、管理分类。
- KS 游戏账号面板：连接状态、环境数、账号数、可执行数、在线数、已选数。
- KS 分类和 KS 环境下拉。
- 执行账号列表，支持在线、KS 可执行、已选状态。
- 命令卡片分组：经济、道具、账号、活动。卡片显示命令名、使用次数、权限、命令内容、标签、参数输入框、使用、复制、编辑、删除。

交互状态：

- 主按钮、次按钮、禁用按钮、hover、focus、active。
- 空状态：未同步到 KS 环境和账号。
- 错误状态：KS Token 已过期。
- 已选账号状态：边框和浅蓝绿底色。
- 可执行账号状态：绿色标签。

响应式：

- 桌面为左侧固定导航 + 右侧任务区。
- 手机为顶部折叠式导航，用户区分行，工具栏单列，命令卡片单列。

输出高保真静态原型，避免紫色 AI 渐变、玻璃拟态、装饰网格和过度动画。

## 7. Codex 高保真复刻要求

- 保留现有接口、ID、onclick 和业务逻辑。
- 可以通过末尾 CSS 设计层覆盖旧样式。
- 不改变已有导航名称和功能入口。
- 重点提升命令管理、KS 目标选择、脚本执行目标、QA、SkillHub 等通用组件的一致性。
- 完成后必须检查脚本解析、Python 编译、设计检测、桌面截图、手机截图和横向溢出。

## 8. 验收标准

- 管理员 5 秒内能看清当前环境、账号、连接状态和命令入口。
- 手机宽度 390px 无横向滚动和控件重叠。
- 所有按钮和输入框在视觉上属于同一套组件。
- 主色不超过一个，状态色只用于状态。
- 没有装饰性网格、彩色发光阴影、营销页式 hero。
